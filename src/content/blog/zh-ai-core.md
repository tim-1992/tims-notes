名词表能让你听懂别人在说什么，但真要把大模型用起来、搭出点东西，绕不开几个"核心机制"——它们不是孤立的词，而是一套套能串起来干活的方法。这篇把最关键的几组讲透：怎么让模型答得准（RAG）、怎么让它自己动手（Agent 与工具）、怎么让它更聪明或更省（推理、MoE、量化）。

> 这些概念比型号稳定得多。RAG、Agent、MCP 这套东西，两三年内都还是搭 AI 应用的地基——**概念是稳定的，型号是流动的**。

## 一、检索增强：让模型答"你自己的事"

大模型只知道训练时喂过的通用知识，不知道你公司的产品文档、你昨天写的笔记。RAG 就是解决这个的。

### 1、RAG（检索增强生成）

先从知识库检索相关资料，再把资料塞进 prompt 让模型据此回答。*场景*：公司客服机器人先去产品文档里搜到相关段落，再据此作答——它答的是"我们公司"的事，而不是瞎编。*好比*开卷考试，答题前先翻到书里那一页。

- **为什么不直接微调**：把知识写进模型（微调）又贵又慢，且资料一更新就得重训；RAG 只改"检索的资料"，文档一改立刻生效，这是它最大的好处。

### 2、知识库（Knowledge Base）

喂给模型的专属资料集合（产品文档、内部 wiki、PDF 等），通常先切块、做 embedding、存进向量库，是 RAG 的"资料源"。*好比*给模型配的一个专用小图书馆。资料的质量和组织，直接决定 RAG 答得好不好——**垃圾进，垃圾出**。

### 3、RAG 全流程（拆开看）

一条完整的检索问答链，六步：

1. **文档切分（Chunking）**：把长文档切成小段。切太大塞不下、检索不准；切太小丢上下文。
2. **向量化（Embedding）**：每段转成向量，存进向量数据库。
3. **检索（Retrieval）**：把用户问题也向量化，找出语义最相近的若干段。
4. **重排序（Rerank）**：对检索结果再精排，留下最相关的，去掉凑数的。
5. **生成（Generation）**：把选中的资料 + 问题一起喂给模型，据此作答。
6. **上下文管理（Context Management）**：控制塞进窗口的总量与顺序，太多会超窗或稀释重点。

  KB[(知识库)] --> R1[① 切分] --> R2[② 向量化] --> VDB[(向量库)]

### 4、RAG 调优（答不准时往哪下手）

检索答得不准，八成不是模型的锅，是检索环节。按这几处依次排查：

- ① **调 chunk 策略**：改切分大小、加重叠（overlap）、按语义/标题切而不是按字数硬切。这是最容易见效的一处。
- ② **升级 embedding 模型**：换更强、更适配你语言/领域的向量模型，检索准度立竿见影。
- ③ **加 reranker**：在检索后加一层重排，把最相关的顶上来。
- ④ **混合检索**：关键词（BM25）+ 向量并用，专有名词、编号这类关键词检索更稳。
- ⑤ **查询改写**：先让模型把用户的口语问题改写得更适合检索，再去查。

<div class="keypoint">
<div class="lbl">踩坑提醒</div>
<p>RAG 出问题时，先别急着换更贵的模型。<strong>九成的"答得不准"都出在检索</strong>——切分乱、embedding 弱、没重排。先把"喂给模型的资料"整对，再谈模型。</p>
</div>



## 二、智能体与工具：让模型"自己动手"

RAG 让模型答得准，但还是一问一答。要让它自己规划、调工具、多步完成任务，就进入 Agent 的世界。

### 1、Agent（智能体）

能自己规划、调用工具、多步执行的 AI，不只是一问一答。*场景*：你说"订下周去上海最便宜的高铁"，它自己查车次、比价、下单一条龙。它和普通对话的区别，是有一个"想→做→看结果→再想"的循环。

### 2、Function Calling / Tool Use（工具调用）

模型按需调用外部函数或 API。*好比*模型发现自己算不准就掏出计算器——查天气、查库、发邮件都靠它，是 Agent 的基础能力。没有工具调用，模型就只会"说"不会"做"。

### 3、Harness（智能体骨架 / 脚手架）

包在模型外面的整套"外壳"——给它工具、喂上下文、控制循环与权限，把只会输出文字的模型变成能真正干活的 agent。*好比*给大脑接上手脚和工具箱。Claude Code、Codex 这类本身就是 harness。同一个模型，套上好的 harness 能力天差地别。

### 4、Workflow（工作流编排）

把多步 agent 任务用确定的流程串起来（谁先谁后、并行还是串行、循环几次），让复杂任务可控、可复现。区别于让模型自由发挥，workflow 是"编排好的剧本"。*好比*流水线 vs 一个人随性干。

- **和 Agent 的取舍**：任务开放、每次都不一样 → 让 Agent 自由发挥；任务固定、要稳定可复现 → 用 Workflow 编排。实战里常两者混用。

### 5、Skill（技能）

把一段可复用的能力或工作流打包好，需要时让模型/agent 直接调用（如 Claude Code 的 Skills、斜杠命令）。*好比*给 AI 装的一个个"插件技能包"，用到时才加载，不占平时的脑容量。

### 6、MCP（Model Context Protocol）

让模型统一接入各种工具和数据源的开放协议。*好比*"AI 界的 USB 接口"——接 Jira、Slack、数据库不用每个都单独造轮子，谁实现了 MCP，就能被任何支持 MCP 的 agent 调用。

## 三、模型能力：多模态与推理

### 1、多模态（Multimodal）

模型能同时处理文字、图片、音频、视频。*比如*拍张冰箱照片问"能做什么菜"，它看图给菜谱；或者丢一段会议录音让它总结。多模态让 AI 从"读写"扩展到"看听"。

### 2、思维链（CoT）/ 推理模型

让模型"先列推理步骤再给结论"，复杂题更准；专门强化这种能力的叫推理模型（如 o 系列、DeepSeek-R1）。*好比*做数学题写草稿而不是直接猜。

- **什么时候用**：数学、代码、多步逻辑推理 → 开推理/思考模式，准度明显上升；简单问答、闲聊 → 别开，又慢又贵还容易想多。



## 四、训练与优化：让模型变强、变省

### 1、RLHF（基于人类反馈的强化学习）

用人类打分"调教"模型，让它更听话、更符合人类偏好。*好比*养宠物，做对给零食，慢慢懂规矩。基座模型只会"续写"，是 RLHF 把它调成了"好用的助手"。

### 2、MoE（专家混合）

模型内部分成多个"专家"，每次只激活一部分。*好比*医院分科，来了病人只叫相关科室——省算力还能撑起超大模型。现在的超大模型（如 DeepSeek-V3）几乎都是 MoE。

### 3、蒸馏（Distillation）

用大模型当老师，把能力"教"给小模型。*好比*名师带出小徒弟，更便宜更快、水平接近。很多好用的小模型，背后都是被大模型蒸馏出来的。

### 4、量化（Quantization）

把权重从高精度压到低精度（16bit→4bit），省显存。*好比*高清视频压成标清，体积小很多、画质略降但能用。本地部署开源模型时，量化几乎是必选项。

<div class="keypoint">
<div class="lbl">一句话记住</div>
<p><strong>MoE</strong>让模型"大而不费"，<strong>蒸馏</strong>让能力"由大传小"，<strong>量化</strong>让模型"塞进小显存"。三招都是在"要能力"和"要便宜/快"之间找平衡。</p>
</div>



## 五、质量与安全：兜底的两道关

### 1、Reranker（重排序）

RAG 里检索出一堆候选后，再用一个模型精挑细选、重新排序，提高喂给模型的资料质量。*好比*初筛简历后，再让资深面试官排个序，把最合适的排前面。加一层 reranker，往往比换 embedding 更省事见效。

### 2、Guardrails（护栏）

给模型输入输出加的安全/合规过滤层，挡住敏感或违规内容。*好比*给强力实习生立的红线和审查——能力越强，护栏越重要。



## 结语

这几组概念不是孤立的：一个成熟的 AI 应用，往往是**用 RAG 喂资料、用 Agent + 工具 + MCP 干活、用 Workflow 把流程编排稳、用 Reranker 和护栏兜底质量**。先理解每块干什么，再看它们怎么串起来，你就能看懂绝大多数 AI 产品的骨架了。
