模型选好了、应用搭起来了，最后一步是让它真正"落地"：跑在哪、花多少钱、数据安不安全、效果好不好。这篇把部署方式、编排平台和评测三件事讲清——都是从"能用"到"用得起、用得稳"绕不开的环节。

> 落地阶段最容易踩的坑不是技术，是**成本和数据**：一个 API 调用几分钱看着不多，量一上来账单吓人；把敏感数据发给云端模型，合规先过不了关。

<div class="keypoint">
<div class="lbl">落地三件事 · 一句话</div>
<p>先决定<strong>跑在哪</strong>（API 还是本地），再看<strong>怎么把流程串起来</strong>（编排/低代码平台），最后用<strong>评测</strong>判断到底行不行。三件事分别对应"部署、编排、评测"。</p>
</div>

## 一、部署与使用：模型跑在哪

### 1、API：最省心

按 token 付费调云端模型，不用管算力和运维。*好比*用自来水，拧开就有、按量付费。

- **优点**：零运维、随时用最新模型、弹性扩缩。
- **缺点**：数据要发出去（合规/隐私顾虑）、量大后成本高、依赖厂商可用性。
- *适合*：绝大多数应用的起步阶段，先跑通再说。

### 2、本地部署：数据不出门

把开源模型（Llama、Qwen、DeepSeek 等）下到自己机器上跑。*好比*自己打口井，前期费劲，后面自给自足。

- **优点**：数据不出门、无按量调用费、可深度定制。
- **缺点**：吃显存、要运维、效果通常追不上最强的闭源旗舰。
- *适合*：数据敏感、调用量极大、或有合规硬要求的场景。
- **Ollama**：把本地跑开源模型变简单的工具，一条命令下载并运行，新手友好。
- **GGUF**：本地部署常见的量化模型文件格式，配合 llama.cpp / Ollama 使用。

### 3、显存（VRAM）：本地部署的硬门槛

本地跑模型，第一道坎就是显存够不够。粗略估算：**4bit 量化下，参数量(B) × 0.6 ≈ 所需显存(GB)**。

- 7B 模型 ≈ 4～5GB，普通游戏显卡能跑。
- 70B 模型 ≈ 40GB+，得专业卡或多卡。
- *还要留余量*：上下文越长、并发越多，额外占用越大。

<div class="keypoint">
<div class="lbl">API 还是本地？三个问题定</div>
<p>① <strong>数据能不能出门</strong>？不能 → 本地。② <strong>调用量多大</strong>？极大且长期 → 本地更划算，否则 API。③ <strong>有没有运维能力/显卡</strong>？没有 → API。多数人答案是"先用 API"，等规模或合规逼上来再考虑本地。</p>
</div>



## 二、编排与低代码平台：把流程串起来

模型是"零件"，真实应用往往要把模型、工具、数据、多步流程拼起来。这类平台让你少写甚至不写代码就能搭。

### 1、主流平台

- **Dify**：开源 LLMOps 平台，可视化搭 RAG 知识库、Agent、工作流，一键发布成 API 或聊天应用。适合快速做企业 AI 应用。
- **n8n**：开源工作流自动化工具（加强版 Zapier），拖拽把各种 App 和 AI 节点连起来跑自动化，自托管友好。
- **Coze / 扣子**（字节）：可视化搭聊天机器人 / Agent 的平台，国内外双版本。
- **Flowise**：开源、基于 LangChain 的可视化拖拽搭建工具。
- **Zapier / Make**：老牌自动化平台，如今都接入了 AI 节点。

### 2、怎么选：自动化 还是 Agent

这类平台大致分两种取向，先想清楚你要哪种：

- **偏自动化流程**（n8n、Zapier、Make）：擅长"触发 → 一步步跑"的确定性流水线，如"收到邮件 → 提取要点 → 存表 → 通知"。*好比*一条流水线，每一站干什么都定死。
- **偏 AI 应用 / Agent**（Dify、Coze、Flowise）：擅长搭"能对话、会检索、可调用工具"的智能应用，如企业知识库问答机器人。*好比*搭一个会思考的助手。
- *经验*：要"把已有系统连起来自动跑"选前者；要"做一个 AI 产品"选后者。两者也常配合用。

## 三、评测：到底行不行、别被刷榜忽悠

选型、上线前后都要评测，否则"感觉不错"根本站不住脚。

### 1、常见评测基准（Benchmark）

衡量模型能力的标准化"考卷"：

- **MMLU**：综合知识（多学科选择题）。
- **SWE-bench**：真实 GitHub issue 修 bug，最贴近工程能力。
- **HumanEval**：写代码、跑通测试。
- **GPQA**：研究生级难题，考深度推理。

### 2、看榜的三条注意

- **别只看分**：基准分高 ≠ 你的场景好用，尤其中文、特定领域。
- **警惕"刷榜"**：为拿高分专门优化，实测体验未必好。*好比*应试刷题拿高分不一定真会用。
- **用自己的数据评**：最靠谱的评测，是拿你真实业务的样本让候选模型都跑一遍，横向对比。

<div class="keypoint">
<div class="lbl">一句话收尾</div>
<p>部署先从 <strong>API</strong> 起步、被成本或合规逼到再上<strong>本地</strong>；流程用<strong>编排平台</strong>串（分清自动化 vs Agent）；效果别信榜单信<strong>自己的数据</strong>。这三步走通，AI 才算真正落了地。</p>
