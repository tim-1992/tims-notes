## 一、基础概念与技术名词
### 一、基础概念

- **Token（词元）**：模型处理文本的最小单位，一个 token 约等于 0.5～1 个中文字 / 0.75 个英文单词。计费和上下文长度都按它算。*好比*出租车按公里计价，模型按 token 计价——发一段长文就是打了趟长途。
- **上下文窗口（Context Window）**：模型一次能"读进去"的 token 上限，超出的会被截断或遗忘。*好比*一张办公桌，摆满了新资料就得把旧的挤下去——所以聊太久，模型会"忘"开头。
- **参数量（Parameters）**：模型内部权重的数量，7B、70B 就是 70 亿、700 亿。*好比*大脑里的神经连接，越多通常越聪明，但也越费电（越贵越慢）。
- **Prompt（提示词）**：你给模型的输入指令。*比如*"帮我把这段总结成三条要点"就是一个 prompt，写得越清楚结果越好。
- **System Prompt（系统提示词）**：开发者预设的"人设和规矩"，优先级高于用户输入。*好比*上班前公司给的员工手册。
- **Zero-shot / Few-shot（零样本 / 少样本）**：不给例子直接问叫 zero-shot；给几个例子再问叫 few-shot。*好比*直接考试 vs 先给你看两道例题。
- **提示词工程（Prompt Engineering）**：系统地设计、调试提示词，让模型稳定给出想要的结果。常用招式：交代身份和目标、给例子（few-shot）、让它先想再答（CoT）、拆步骤。*好比*不是碰运气，而是把需求"讲明白"的手艺。
- **上下文工程（Context Engineering）**：比提示词工程更大的概念——统筹"往上下文窗口里放什么"：检索到的资料（RAG）、历史记忆、工具返回、精简压缩等，让模型每一步都拿到刚好够用的信息。*好比*不只写好一句话，而是布置好模型的整张"工作台"。
- **Temperature（温度）**：控制输出随机性。低温稳定保守（适合写代码、做数据），高温发散有创意（适合起名、头脑风暴）。
- **Top-p（核采样）**：另一个控制随机性的旋钮，限定模型只从概率最高的一小撮候选词里挑。和 temperature 二选一调即可。
- **流式输出（Streaming）**：一个字一个字往外蹦，而不是憋完整段再给你。*好比*边想边说，体验上更快。
- **Embedding（向量化）**：把文本转成一串数字，语义相近的文本数字也相近。*好比*给每句话标"经纬度坐标"，意思接近坐标就挨得近——搜索和 RAG 靠它。
- **预训练（Pre-training）**：用海量数据把基础模型练出来，代价极高，通常只有大厂做。*好比*一个人从小读完整座图书馆。
- **微调（Fine-tuning）/ LoRA**：在预训练模型上用少量特定数据再训练，贴合某个任务或风格；LoRA 是一种只训练少量新增参数的轻量微调法，省钱省显存。*好比*博学的人再做几周岗前培训。
- **推理（Inference）**：模型实际"跑起来"生成结果的过程，对应训练阶段。*好比*学完之后真正上考场答题。

### 二、核心技术与能力

- **RAG（检索增强生成）**：先从知识库检索相关资料，再塞进 prompt 让模型回答。*场景*：公司客服机器人先去产品文档搜到相关段落再回答，这样它答的是"我们公司"的事，而不是瞎编。
- **知识库（Knowledge Base）**：喂给模型的专属资料集合（产品文档、内部 wiki、PDF 等），通常先切块、做 embedding、存进向量库，是 RAG 的"资料源"。*好比*给模型配的一个专用小图书馆。
- **RAG 全流程（拆开看）**：一条完整的检索问答链，六步——
  1. **文档切分（Chunking）**：把长文档切成小段。切太大塞不下、检索不准；切太小丢上下文。
  2. **向量化（Embedding）**：每段转成向量，存进向量数据库。
  3. **检索（Retrieval）**：把用户问题也向量化，找出语义最相近的若干段。
  4. **重排序（Rerank）**：对检索结果再精排，留下最相关的，去掉凑数的。
  5. **生成（Generation）**：把选中的资料 + 问题一起喂给模型，据此作答。
  6. **上下文管理（Context Management）**：控制塞进窗口的总量与顺序，太多会超窗或稀释重点（详见上文"上下文工程"）。

  R5 --- R6[⑥ 上下文管理]
</pre>
- **RAG 调优常用手段**：检索答得不准时，按这几处下手——① **调 chunk 策略**：改切分大小、加重叠(overlap)、按语义/标题切而不是按字数硬切；② **升级 embedding 模型**：换更强、更适配你语言/领域的向量模型，检索准度立竿见影；③ **加 reranker**：在检索后加一层重排，把最相关的顶上来；④ 进阶还可用**混合检索**（关键词 + 向量并用）、**查询改写**（先让模型把问题改写得更好检索）。
- **Skill / 技能**：把一段可复用的能力或工作流打包好，需要时让模型/agent 直接调用（如 Claude Code 的 Skills、斜杠命令）。*好比*给 AI 装的一个个"插件技能包"。
- **Agent（智能体）**：能自己规划、调用工具、多步执行的 AI，不只是一问一答。*场景*：你说"订下周去上海最便宜的高铁"，它自己查车次、比价、下单一条龙。
- **Function Calling / Tool Use（工具调用）**：模型按需调用外部函数或 API。*好比*模型发现自己算不准就掏出计算器——查天气、查库、发邮件都靠它，是 Agent 的基础。
- **Harness（智能体骨架 / 脚手架）**：包在模型外面的整套"外壳"——给它工具、喂上下文、控制循环与权限，把只会输出文字的模型变成能真正干活的 agent。*好比*给大脑接上手脚和工具箱。Claude Code、Codex 这类本身就是 harness。
- **Workflow（工作流编排）**：把多步 agent 任务用确定的流程串起来（谁先谁后、并行还是串行、循环几次），让复杂任务可控、可复现。区别于让模型自由发挥，workflow 是"编排好的剧本"。*好比*流水线 vs 一个人随性干。
- **MCP（Model Context Protocol）**：让模型统一接入各种工具和数据源的开放协议。*好比*"AI 界的 USB 接口"，接 Jira、Slack、数据库不用每个都单独造轮子。
- **多模态（Multimodal）**：模型能同时处理文字、图片、音频、视频。*比如*拍张冰箱照片问"能做什么菜"，它看图给菜谱。
- **思维链（CoT）/ 推理模型**：让模型"先列推理步骤再给结论"，复杂题更准；专门强化这种能力的叫推理模型（如 o 系列、DeepSeek-R1）。*好比*做数学题写草稿而不是直接猜。
- **RLHF（基于人类反馈的强化学习）**：用人类打分"调教"模型，让它更听话。*好比*养宠物，做对给零食，慢慢懂规矩。
- **MoE（专家混合）**：模型内部分成多个"专家"，每次只激活一部分。*好比*医院分科，来了病人只叫相关科室，省算力还能撑起超大模型。
- **蒸馏（Distillation）**：用大模型当老师把能力"教"给小模型。*好比*名师带出小徒弟，更便宜更快、水平接近。
- **量化（Quantization）**：把权重从高精度压到低精度（16bit→4bit），省显存。*好比*高清视频压成标清，体积小很多、画质略降但能用。
- **Reranker（重排序）**：RAG 里检索出一堆候选后，再用一个模型精挑细选、重新排序，提高喂给模型的资料质量。
- **Guardrails（护栏）**：给模型输入输出加的安全/合规过滤层，挡住敏感或违规内容。

### 三、圈内黑话

- **幻觉（Hallucination）**：模型一本正经胡说八道，编造不存在的事实或引用。*比如*问它某书哪一页，它给你编个页码和原文，听着都对其实全假。
- **对齐（Alignment）**：让模型行为符合人类价值观和意图。*好比*给能力很强的实习生立规矩。
- **越狱（Jailbreak）**：用特殊话术绕过安全限制，诱导它输出本该拒绝的内容。
- **涌现（Emergence）**：规模大到一定程度突然冒出小模型没有的能力。*好比*水加热到 100 度突然沸腾——量变到质变。
- **Scaling Law（缩放定律）**：能力随参数、数据、算力增加而可预测提升，即"大力出奇迹"。
- **AGI（通用人工智能）**：能像人一样胜任各种任务的 AI，目前仍是目标而非现实。
- **刷榜**：为在榜单拿高分专门优化，不一定代表真实体验好。*好比*应试刷题拿高分不一定真会用。
- **开源 / 闭源**：权重是否公开。闭源（GPT、Claude、Gemini）只能调 API；开源（Llama、Qwen、DeepSeek）可自己下载部署。*好比*餐厅只卖成品 vs 直接给你菜谱。



## 二、厂商与模型



搞懂了概念，再来认认这些名字背后是哪些公司、哪些模型、分别给谁用。

> 型号更新极快，以下为大致格局，认准"厂商 + 分档逻辑"即可——**概念是稳定的，型号是流动的**。

### 一、主流厂商与代表模型

- **OpenAI**：闭源标杆。当前 GPT-5.6 系列分 **Sol**（复杂专业任务）/ **Terra**（性价比均衡）/ **Luna**（低成本高并发）三档，另有安全向 Cyber、图像 GPT Image、实时语音等；历史上的 **o 系列**是主打推理的产品线。
- **Anthropic**：主打安全对齐、长文本、写代码。当前旗舰 **Claude Fable 5**（面向长时程 agent，最强），下面 **Opus 5**（复杂 agentic 编码/企业）、**Sonnet 5**（速度与智能最佳平衡）、**Haiku 4.5**（最快、接近前沿）三档。分档逻辑：Opus 最强、Sonnet 均衡、Haiku 最快。
- **Google**：多模态和超长上下文见长。**Gemini** 分 **Pro**（最强推理/编码）/ **Flash**（低延迟性价比）/ **Flash-Lite**（最便宜最快）/ **Nano**（端侧）；当前主力为 Gemini 3.x 与 2.5。配套 **Veo**（视频）、**Imagen / Nano Banana**（图像）。
- **Meta**：**Llama** 系列，开源阵营代表，催生大量社区衍生模型。
- **Mistral**：法国厂商，开源 + 商用并行，小而精。
- **DeepSeek（深度求索）**：国产，高性价比 + 强推理/代码出圈，开源影响力大（版本演变见文末）。
- **阿里 · 通义千问（Qwen）**：国产开源主力之一，模型矩阵全、社区活跃。
- **字节 · 豆包（Doubao）**：主打 C 端应用和低价 API。
- **月之暗面 · Kimi**：以超长上下文起家。
- **智谱 · GLM**：学术出身，模型与商用并重。
- **xAI · Grok**：马斯克旗下，深度绑定 X（推特）。

### 二、面向用户的 AI 应用/产品

上面是"发动机"（模型），这里是普通人直接用的"整车"（产品）。

- **ChatGPT**（OpenAI）：把 AI 带进大众视野的对话产品，如今集成搜索、画图、语音、Agent。
- **Claude**（Anthropic）：以写作、编码、长文档处理见长的对话产品。
- **Gemini App**（Google）：深度整合搜索与安卓/办公生态。
- **Perplexity**：主打"AI 搜索/答案引擎"，边搜边答、带来源引用，适合查资料。
- **Grok**（xAI）：集成在 X 里，实时性强、风格更"放"。
- **Poe**（Quora）：一个入口聚合调用多家模型。
- **NotebookLM**（Google）：把你上传的资料变成可问答、可生成播客的笔记本。
- **国内**：豆包、Kimi、通义、文心一言、腾讯元宝等。

### 三、案例：DeepSeek 模型演变

看一个真实模型怎么一代代进化，比记名字更有感觉。

- **V2.5**（2024-09）：合并原来的 Chat 与 Coder，通用 + 代码一体化。
- **V3**（2024-12）：`deepseek-chat` 大升级，671B MoE 架构，通用能力显著增强。
- **R1**（2025-01）：首个推理模型，支持"思考模式"，数学/代码大涨，凭开源 + 高性价比引爆全球关注。
- **V3.1**（2025-08）：混合架构，一个模型同时支持思考 / 非思考两种模式。
- **V3.1-Terminus**（2025-09）：修复中英文混杂，Code / Search Agent 增强。
- **V3.2**（2025-12，先出 Exp 实验版）：稳定版，思考与非思考模式分离。
- **V4-Flash**（2026-07）：公测，主打快，Agent 能力大幅提升。
- **V4-Pro**（2026-08）：正式版，Agent 性能巅峰，思考强度可调（low / high / max）。

主线：**通用（V2.5→V3）→ 推理（R1）→ 思考/非思考合一（V3.1→V3.2）→ 强 Agent（V4）**。

## 三、工具与平台



概念懂了、模型认识了，这篇讲怎么真正拿它干活——从写代码的工具，到搭应用的平台，到跑起来的部署方式。

### 一、AI 编程工具

- **GitHub Copilot**：最早火起来的 AI 代码补全，编辑器里边写边提示。*好比*随时补全下一句的搭子。
- **Cursor**：内置 AI 的代码编辑器（VS Code 魔改），主打对话式改代码、整仓理解。
- **Claude Code**：Anthropic 的命令行 AI 编程 agent，跨文件读写、跑命令、多步完成任务（演变见文末）。
- **OpenAI Codex**：OpenAI 的 AI 编程 agent 产品线。名字有历史：早年 Codex 是给 Copilot 供能的代码模型；如今 **Codex** 指 OpenAI 的编程 agent，有命令行版（Codex CLI）、IDE 集成和云端版，能读懂整仓、自己写代码、跑测试、改 bug，背后跑 GPT 系列模型。定位对标 Claude Code。
- **Aider**：命令行 AI 结对编程，直接读写 git 仓库、自动提交，适合终端党。
- **Windsurf / Cline**：同类 AI 编程工具/插件，主打 agent 式自动改代码。
- **v0 / Bolt / Lovable**：主打"一句话生成前端/整个应用"的 AI 建站工具。
- **Vibe Coding（氛围编程）**：新兴黑话，指基本靠自然语言指挥 AI 写代码、自己少动手。

> 命令行工具（Claude Code / Codex / Aider）在 Windows 上用 **WSL2 + Windows Terminal** 体验最接近 Mac/Linux。

### 二、编排与低代码平台

把模型、工具、数据、流程用可视化方式拼起来，少写甚至不写代码就能搭 AI 应用。

- **Dify**：开源 LLMOps 平台，可视化搭 RAG 知识库、Agent、工作流，一键发布成 API 或聊天应用。适合快速做企业 AI 应用。
- **n8n**：开源工作流自动化工具（类似加强版 Zapier），拖拽把各种 App 和 AI 节点连起来跑自动化，自托管友好。
- **Coze / 扣子**（字节）：可视化搭聊天机器人/Agent 的平台，国内外双版本。
- **Flowise**：开源、基于 LangChain 的可视化拖拽搭建工具。
- **Zapier / Make**：老牌自动化平台，现都接入了 AI 节点。

### 三、开发框架与生态

- **LangChain**：最流行的 LLM 应用开发框架之一，把 prompt、模型、工具、记忆、检索串成"链"。*好比*搭 AI 应用的乐高积木。
- **LlamaIndex**：偏数据接入和检索的框架，专注把私有数据喂给模型（RAG 常用）。
- **LangGraph**：LangChain 的进阶库，用图结构编排更复杂、可循环的 Agent 流程。
- **向量数据库（Vector DB）**：专存 embedding、做相似度检索，如 Pinecone、Milvus、Chroma、pgvector，是 RAG 的存储底座。
- **Hugging Face**："AI 界的 GitHub"，开源模型和数据集最大集散地，也提供 transformers 等库。

### 四、部署与使用

- **API**：最省心，按 token 付费调云端模型，不用管算力。*好比*用自来水，拧开就有、按量付费。
- **本地部署**：把开源模型下到自己机器跑，数据不出门、无调用费，但吃显存。*好比*自己打口井，前期费劲后面自给自足。
- **Ollama**：把本地跑开源模型变简单的工具，一条命令下载并运行。
- **GGUF**：本地部署常见的量化模型文件格式，配合 llama.cpp / Ollama 用。
- **显存（VRAM）**：本地跑模型的硬门槛。粗略估：4bit 量化下，参数量(B) × 0.6 ≈ 所需显存(GB)。

### 五、生成式媒体与评测

- **扩散模型（Diffusion）**：文生图/视频的主流技术，从一团噪点一步步"去噪"生成图像。
- **文生图**：Midjourney、Stable Diffusion（开源）、DALL·E、谷歌 Imagen / Nano Banana 等。
- **文生视频**：OpenAI Sora、谷歌 Veo、快手可灵（Kling）、Runway 等。
- **TTS / ASR**：TTS 是文字转语音（语音合成），ASR 是语音转文字（语音识别）。
- **评测基准（Benchmark）**：衡量模型能力的标准化考卷，如 MMLU（综合知识）、SWE-bench（真实修 bug）、HumanEval（写代码）、GPQA（研究生难题）。看榜别只看分，留意"刷榜"。

### 六、案例：Claude Code 演变

Anthropic 的命令行 AI 编程 agent，2025 年推出。它不走 V1/V2 大版本号，而是**后台持续自动更新**，靠能力里程碑迭代：

- 起步：终端 CLI，跨文件读写、跑命令、自动 commit。
- 编辑器接入：VS Code / JetBrains 扩展，行内 diff、@ 引用。
- 连接外部：通过 **MCP** 接入 Jira、Slack、Google Drive 等。
- 定制化：**CLAUDE.md** 记忆、**Hooks**（操作前后跑脚本）、**Skills**（打包可复用工作流 / 斜杠命令）。
- 多 agent：子代理、Agent 团队、后台并行会话、动态工作流编排。
- 全端化：桌面 App、网页版（claude.ai/code）、移动端，同一引擎跨端共享配置。
- 自动化：Routines 云端定时任务、GitHub Actions 自动 review。

主线：**终端工具 → 多端 + 生态接入 → 可编排的 agent 平台**。
